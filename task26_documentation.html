📌 1. Project Overview & Scenario

This technical report documents the end-to-end design, implementation, and execution of a real-time stream processing pipeline built for CartStream Analytics, an international e-commerce platform.

The platform ingests a continuous stream of user interaction events (including product views view, additions to cart cart, removals from cart remove_from_cart, and completed purchase transactions purchase). Utilizing Apache Flink SQL, this pipeline enforces Event-Time Processing and Bounded Out-of-Orderness Watermarks to deliver precise, deterministic real-time revenue analytics.

🎯 Core Technical Objectives:
  • 5-Minute Window Aggregations: Process live streams in non-overlapping 5-minute intervals using modern TUMBLE Table-Valued Functions (TVFs).
  • Key Metric Calculations: Calculate completed orders (total_orders), gross revenue (gross_revenue), average order value (avg_order_value), and unique buyers (unique_buyers).
  • Handling Real-World Data Challenges: Gracefully process missing brand names via COALESCE and handle out-of-order event arrivals across network boundaries.

📑 3. Dataset Specification & Field Schema

The pipeline operates on a sample stream of 50,000 continuous event records covering 3.5 hours of continuous activity, derived from the Kaggle E-Commerce Events History dataset:

Property Name Flink SQL Datatype Analytical Description & Processing Usage
event_time TIMESTAMP(3) (RowTime) Native event timestamp with watermark rule: WATERMARK FOR event_time AS event_time - INTERVAL '5' SECOND.
event_type VARCHAR Interaction category. Filtered explicitly to completed purchase transactions: WHERE event_type = 'purchase'.
brand VARCHAR Product brand name. Safeguarded against nulls using COALESCE(NULLIF(TRIM(brand), ''), 'UNKNOWN').
price DECIMAL(10, 2) Item purchase price in USD. Aggregated to compute revenue (SUM) and average order value (AVG).
user_id BIGINT Permanent user identifier. Used to calculate unique purchasers per window: COUNT(DISTINCT user_id).
user_session VARCHAR Unique user session token generated during checkout.

🧠 4. Theoretical Answer: 5-Second Watermark Strategy

❓ Question: Explain how this 5-second watermark boundary ensures deterministic window processing for out-of-order event arrivals.

Detailed Engineering Explanation:

  1. Network Latency & Out-of-Order Arrival: In real-world e-commerce networks, event packets generated at 10:04:58 might arrive at the processing engine at 10:05:02 due to variable network latency or temporary client disconnection.
  2. Event Time vs. Processing Time: Apache Flink relies on the timestamp embedded within the data record itself (Event Time) rather than the wall-clock time of the server (Processing Time).
  3. Slack / Tolerance Window Mechanics: By defining WATERMARK FOR event_time AS event_time - INTERVAL '5' SECOND, Flink grants a 5-second grace period for delayed records. A window spanning [10:00:00, 10:05:00) will not evaluate or close until Flink observes an event timestamp reaching or exceeding 10:05:05.
  4. Guaranteed Determinism: This mechanism guarantees that delayed events falling within the 5-second window are properly routed to their correct time window, yielding 100% deterministic and reproducible analytics across pipeline executions.

💻 5. Flink SQL Pipeline Implementation Code

The complete pipeline DDL and window aggregation query are maintained in flink_ecommerce_pipeline.sql:

-- Enable Flink Streaming Runtime Mode
SET 'execution.runtime-mode' = 'streaming';

-- 1. Streaming Source Table DDL
CREATE TABLE ecommerce_events (
    event_time_str  VARCHAR,
    event_type      VARCHAR,
    product_id      BIGINT,
    category_id     BIGINT,
    category_code   VARCHAR,
    brand           VARCHAR,
    price           DECIMAL(10, 2),
    user_id         BIGINT,
    user_session    VARCHAR,
    event_time AS COALESCE(TO_TIMESTAMP(event_time_str, 'yyyy-MM-dd HH:mm:ss z'), TIMESTAMP '1970-01-01 00:00:00'),
    WATERMARK FOR event_time AS event_time - INTERVAL '5' SECOND
) WITH (
    'connector' = 'filesystem',
    'path' = '/opt/flink/data/events_sample.csv',
    'format' = 'csv',
    'csv.ignore-parse-errors' = 'true',
    'csv.allow-comments' = 'true'
);

-- 2. Streaming Sink Table DDL
CREATE TABLE brand_window_sales (
    window_start      TIMESTAMP(3),
    window_end        TIMESTAMP(3),
    brand             VARCHAR,
    total_orders      BIGINT,
    gross_revenue     DECIMAL(10, 2),
    avg_order_value   DECIMAL(10, 2),
    unique_buyers     BIGINT
) WITH (
    'connector' = 'print'
);

-- 3. Windowing TVF & Real-Time Aggregation Query
INSERT INTO brand_window_sales
SELECT
    window_start,
    window_end,
    COALESCE(NULLIF(TRIM(brand), ''), 'UNKNOWN') AS brand,
    COUNT(1) AS total_orders,
    ROUND(SUM(price), 2) AS gross_revenue,
    ROUND(AVG(price), 2) AS avg_order_value,
    COUNT(DISTINCT user_id) AS unique_buyers
FROM TABLE(
    TUMBLE(
        TABLE ecommerce_events,
        DESCRIPTOR(event_time),
        INTERVAL '5' MINUTE
    )
)
WHERE event_type = 'purchase'
GROUP BY 
    window_start, 
    window_end, 
    COALESCE(NULLIF(TRIM(brand), ''), 'UNKNOWN');

📌 1. نظرة عامة على المشروع (Executive Overview)

يهدف هذا التقرير إلى توثيق خط معالجة البيانات الفوري (Real-Time Stream Processing Pipeline) المصمم لمتابعة تحليلات متجر التجارة الإلكترونية الدولي CartStream Analytics.

تستقبل المنصة دفقاً حياً مستمراً من تفاعلات وسلوكيات المشترين (تصفح view، إضافة لسلة التسوق cart، إزالة من السلة remove_from_cart، وحركات شراء مكتملة purchase). قمنا ببناء خط التجميع بالاعتماد على Apache Flink SQL مع تطبيق معالجة زمن الحدث Event-Time Processing وعلامات التزامن المائية Watermarks لتقديم مؤشرات أداء دقيقة وحتمية.

🎯 أهداف المنظومة الرئيسية:
  • تجميع المبيعات حياً كل 5 دقائق عبر TUMBLE Table-Valued Functions (TVFs).
  • استخراج مؤشرات الأعمال الدقيقة (إجمالي الطلبات المكتملة total_orders، الإيرادات gross_revenue، متوسط قيمة الطلب avg_order_value، والمشترين الفريدين unique_buyers).
  • معالجة تحديات البيانات الواقعية (القيم المفقودة NULL في العلامات التجارية، وتأخير البيانات عبر الشبكة Out-of-Order Events).

📑 3. هيكل الحقول والبيانات (Dataset Specification)

تم الاعتماد على عينة أحداث واقعية تغطي 3.5 ساعات متواصلة بحجم 50,000 سجل مأخوذة من قاعدة بيانات التجارة الإلكترونية العالمية على Kaggle:

الحقل (Property) نوع البيانات (Flink SQL) الوصف والأهمية التحليلية
event_time TIMESTAMP(3) (RowTime) توقيت وقوع الحدث الأصلي مع إضافة WATERMARK FOR event_time AS event_time - INTERVAL '5' SECOND.
event_type VARCHAR نوع التفاعل (تتم الفلترة على WHERE event_type = 'purchase' للطلبات الناجحة).
brand VARCHAR اسم الماركة التجارية، وتتم معالجته عبر COALESCE(NULLIF(TRIM(brand), ''), 'UNKNOWN').
price DECIMAL(10, 2) سعر المنتج المشتري بالدولار، ويُستخدم في حساب الإيرادات ومعدل قيمة الطلبات.
user_id BIGINT المعرف الفريد للمستخدم، لحساب عدد المشترين الفريدين عبر COUNT(DISTINCT user_id).
user_session VARCHAR معرف الجلسة الفريد المتولد أثناء عملية الشراء.

🧠 4. الإجابة النظرية: استراتيجية الـ 5-Second Watermark

❓ السؤال النظري: كيف تضمن الـ 5-Second Watermark معالجة حتمية ودقيقة للنوافذ الزمنية؟

الإجابة الهندسية التفصيلية:

  1. تحدي وصول الأحداث غير المرتبة (Out-of-Order Arrivals): في بيئات الشبكات الحقيقية، قد يتأخر وصول حدث وقع في الساعة 10:04:58 ليصل إلى السيرفر في 10:05:02 بسبب بطء الاتصال.
  2. ساعة البيانات (Event Time vs Processing Time): يعتمد Flink على الطابع الزمني المكتوب داخل الحدث نفسه (Event Time) وليس وقت السيرفر الحالي.
  3. فترة السماح (Slack Tolerance Window): من خلال التعبير event_time - INTERVAL '5' SECOND، يمنح Flink مهلة قدرها 5 ثوانٍ لأي حدث متأخر، فلا يتم إغلاق النافذة الزمنية [10:00:00, 10:05:00) حتى يشاهد Flink حدثاً توقيته يسبق النافذة بـ 5 ثوانٍ (أي عند وصول حدث توقيته 10:05:05).
  4. النتيجة الحتمية (Deterministic Output): يضمن ذلك دخول كافة الأحداث المتأخرة ضمن نافذتها الصحيحة بدون فقدان للبيانات، مما يجعل مخرجات التحليل متطابقة تماماً في كل مرة يتم فيها إعادة تشغيل التجميع.

💻 5. كود الاستعلام المعتمد (Flink SQL Code)

تمت كتابة وتوثيق كود التجميع كاملاً داخل الملف flink_ecommerce_pipeline.sql:

-- Enable Flink Streaming Runtime Mode
SET 'execution.runtime-mode' = 'streaming';

-- 1. Streaming Source Table DDL
CREATE TABLE ecommerce_events (
    event_time_str  VARCHAR,
    event_type      VARCHAR,
    product_id      BIGINT,
    category_id     BIGINT,
    category_code   VARCHAR,
    brand           VARCHAR,
    price           DECIMAL(10, 2),
    user_id         BIGINT,
    user_session    VARCHAR,
    event_time AS COALESCE(TO_TIMESTAMP(event_time_str, 'yyyy-MM-dd HH:mm:ss z'), TIMESTAMP '1970-01-01 00:00:00'),
    WATERMARK FOR event_time AS event_time - INTERVAL '5' SECOND
) WITH (
    'connector' = 'filesystem',
    'path' = '/opt/flink/data/events_sample.csv',
    'format' = 'csv',
    'csv.ignore-parse-errors' = 'true',
    'csv.allow-comments' = 'true'
);

-- 2. Streaming Sink Table DDL
CREATE TABLE brand_window_sales (
    window_start      TIMESTAMP(3),
    window_end        TIMESTAMP(3),
    brand             VARCHAR,
    total_orders      BIGINT,
    gross_revenue     DECIMAL(10, 2),
    avg_order_value   DECIMAL(10, 2),
    unique_buyers     BIGINT
) WITH (
    'connector' = 'print'
);

-- 3. Windowing TVF & Real-Time Aggregation Query
INSERT INTO brand_window_sales
SELECT
    window_start,
    window_end,
    COALESCE(NULLIF(TRIM(brand), ''), 'UNKNOWN') AS brand,
    COUNT(1) AS total_orders,
    ROUND(SUM(price), 2) AS gross_revenue,
    ROUND(AVG(price), 2) AS avg_order_value,
    COUNT(DISTINCT user_id) AS unique_buyers
FROM TABLE(
    TUMBLE(
        TABLE ecommerce_events,
        DESCRIPTOR(event_time),
        INTERVAL '5' MINUTE
    )
)
WHERE event_type = 'purchase'
GROUP BY 
    window_start, 
    window_end, 
    COALESCE(NULLIF(TRIM(brand), ''), 'UNKNOWN');
